## Portable Juss OS command surface

The shared portable command names below are reasoning/planning modes only. They never grant tool, provider, checkout, payment, publication, deployment, production, customer-data, credential, or founder authority, and they never weaken this repository's stricter commerce, privacy, brand, evidence, rollback, or approval rules.

- `/goalfix` — identify the exact evidence-backed fix, preserve the full correctness boundary, keep it reversible, and verify before integration.
- `/ultrathink` — widen the reasoning pass, inspect coupled constraints, and synthesize the strongest evidence-backed path before acting.
- `/truthmode` — separate verified fact, inference, unknowns, and blockers; never upgrade assumption into repository or production truth.
- `/confess` — surface uncertainty, shortcuts, contradictions, missing proof, or uncomfortable failure modes before declaring completion.
- `/redteam` — attack the premise and selected implementation, including commerce, privacy, payment, deployment, and rollback failure modes.
- `/lindymode` — prefer durable, legible, maintainable choices that reduce long-term operational and governance drift.
- `/ooda` — observe current evidence, orient to repository-local constraints, decide the narrow next action, act, then re-observe before continuing.
- `/visualize` — create or refine an editable visual plan from verified state; visual output is not checkout, catalog, payment, Worker, domain, deployment, or runtime proof.

These aliases supplement the existing founder loop, repository operator skill, `/sales`, `/devil`, Figma skill, exact-head checks, Playwright requirements, and explicit founder gates. When a local rule is stricter, the local rule wins.
